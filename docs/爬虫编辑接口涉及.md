
编辑爬虫任务涉及的接口和页面如下。

---

## 一、涉及接口（后端）

| 方法 | 路径 | 说明 | 所在文件 |
|------|------|------|----------|
| **PATCH** | `/api/tasks/{task_id}` | 更新任务（编辑任务的主接口） | `src/api/routes/tasks.py` → `update_task` |
| **GET** | `/api/tasks` | 获取任务列表（编辑前/后刷新列表） | 同上 → `get_tasks` |
| **GET** | `/api/tasks/{task_id}` | 获取单个任务（按需拉取当前任务数据） | 同上 → `get_task` |

编辑流程里实际会用到的是：

- **PATCH `/api/tasks/{task_id}`**：提交编辑内容，请求体为 `TaskUpdate`（见下）。
- 前端列表一般用 **GET `/api/tasks`** 拉列表，编辑弹窗用当前行数据，不一定会再调 GET 单任务。

---

## 二、接口详情：PATCH 更新任务

- **路由**：`src/api/routes/tasks.py` 第 116–190 行，`update_task(task_id, task_update: TaskUpdate)`。
- **请求体**：`TaskUpdate`（`src/domain/models/task.py` 第 259–288 行），字段均为可选，只传要改的项即可，例如：
  - `task_name`, `enabled`, `keyword`, `description`
  - `analyze_images`, `max_pages`, `personal_only`, `min_price`, `max_price`
  - `cron`, `ai_prompt_base_file`, `ai_prompt_criteria_file`, `account_state_file`
  - `free_shipping`, `new_publish_option`, `region`
  - `decision_mode`, `keyword_rules`, `hooks`, `hook_params`, `is_running`
- **后端流程**：先 `get_task` 校验存在 → 若切到 AI 模式或改了 description 会触发重新生成 criteria 文件 → `TaskService.update_task` 写库 → `_reload_scheduler_if_needed` 重载定时任务。

## 三、涉及页面与组件（前端）

| 类型 | 路径 | 说明 |
|------|------|------|
| 路由页 | `/tasks`（name: `Tasks`） | 任务管理页，承载编辑入口和编辑弹窗 |
| 视图 | `web-ui/src/views/TasksView.vue` | 任务列表 + 编辑弹窗 + 删除/启用开关等 |
| 列表组件 | `web-ui/src/components/tasks/TasksTable.vue` | 表格，每行有「编辑」按钮，触发 `edit-task` |
| 表单组件 | `web-ui/src/components/tasks/TaskForm.vue` | 创建/编辑共用表单，`mode="edit"` 时用 `initialData` 预填 |

**编辑流程（前端）：**

1. 用户在 **任务管理页** `/tasks`（`TasksView.vue`）的表格里点某一行的「编辑」。
2. `TasksTable.vue` 发出 `@edit-task`，把当前行 `task` 传给 `TasksView`。
3. `TasksView` 里 `handleEditTask(task)` 设置 `selectedTask`、打开编辑弹窗 `isEditDialogOpen = true`。
4. 弹窗里用 **TaskForm**，`mode="edit"`、`:initial-data="selectedTask"`，用户改完后点「保存更改」。
5. 触发表单的 `@submit`，在 `TasksView` 里执行 `handleUpdateTask(data)`，调用 `updateTask(selectedTask.id, data)`。
6. `useTasks` 的 `updateTask` 内部请求 **PATCH `/api/tasks/${taskId}`**（见 `web-ui/src/api/tasks.ts` 的 `updateTask`）。

另外，同一页还有：

- **「重新生成 AI 标准」弹窗**：只改 `description` 并提交，也会走 **PATCH `/api/tasks/{task_id}`**（只传 `{ description }`），见 `handleRefreshCriteria`。
- **启用/禁用开关**：`handleToggleEnabled` 同样调用 **PATCH**，只传 `{ enabled }`。

## 四、前端 API 与 composable

| 文件 | 作用 |
|------|------|
| `web-ui/src/api/tasks.ts` | `updateTask(taskId, data)`：发 PATCH `/api/tasks/{taskId}`，返回 `result.task` |
| `web-ui/src/composables/useTasks.ts` | `updateTask(taskId, data)`：调用上面 API，并更新本地 `tasks` 列表里对应项 |

---

## 五、小结

- **编辑任务主接口**：**PATCH `/api/tasks/{task_id}`**，实现位于 `src/api/routes/tasks.py` 的 `update_task`。
- **编辑涉及页面**：仅 **任务管理页** `/tasks`，由 `TasksView.vue` 承载，用 `TasksTable.vue` 的编辑按钮打开弹窗，弹窗内用 `TaskForm.vue`（`mode="edit"`）提交，提交时通过 `api/tasks.ts` 的 `updateTask` 调用上述 PATCH 接口。
